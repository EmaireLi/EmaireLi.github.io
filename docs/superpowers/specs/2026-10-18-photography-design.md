# 独立摄影相册第一版

依据本次用户已确定方案实施，不把历史提案作为授权。保留主站风格与现有功能；首页仅增摄影入口。`photos/` 管页面和 JSON，`assets/photos/` 仅放生成展示图。原有 gallery/posts 目录用途不变。

## 结构与交互

采用原生 ES 模块、JSON 和 dialog，无运行时后端、第三方脚本或字体。照片按 JSON 数组顺序显示；每张照片可属于一个相册，未归类照片仍在全部作品中。照片墙按行排列以保持阅读及键盘顺序，保留比例、不裁切；优先保证构图而非填满每个空隙。替代方案 CSS 多列会造成纵向阅读顺序，JS 瀑布流增加布局复杂度，第一版不用。

默认全部，按钮筛选相册；查看器只在打开后请求查看图，支持方向键、Esc、单指横滑、焦点锁定与恢复。数据、缩略图与查看图各有失败提示及重试。空内容明确呈现，无借用照片。精选轮播不纳入首版。

## 管理与发布

管理页从固定目标 EmaireLi/EmaireLi.github.io 的 main 读取精确 commit 下的资料；可先离线编辑，但发布必须连接并核对基线。Token 仅保留在页面内存和密码输入控件，pagehide/主动清除时移除，不持久化；页面 CSP 限定脚本与网络源。仅需该仓库 Contents read/write，权限并非目录级。

照片、相册、排序编辑在内存进行；删除确认；发布前逐条摘要，再明确点击发布。串行处理单张文件，释放 bitmap/canvas；限制单批数量及生成图总大小。暂用缩略长边 960、查看长边 3200、JPEG 0.86/0.90，允许调整和查看输出，必须用真实 S5M2 样片后再定稿。只接受浏览器可解码 JPEG/PNG/WebP，不声称 RAW/HEIC 或原图备份支持。大图解码仍可能因设备内存失败。

Git blobs → 单个 tree → 单个 commit → force:false 更新 ref。比较读取基线、发布前与更新前的 head；遇变动停止，不自动覆盖或重放。请求超时、限流、权限失败明确提示，保留草稿。更新响应丢失时查询 head 判断是否成功，无法确认则提示查提交记录再操作。所有图片与 JSON 合并一次提交，删除也同步移除原展示图。保留可选 originalUrl/originalBytes，没有真实 HTTPS URL 不显示链接。

## 验证与边界

模拟请求验证原子发布、冲突、限流、失败和不确定结果；用临时合成图片验证浏览器布局、筛选、顺序、焦点、触控、失败回退、压缩与 Token 生命周期。合成测试材料不发布。真实照片、质量定稿、真实 Token 上传未提供时明确未验证。只提交任务文件，保留 smartlabeling 未提交修改。推送、Actions 部署、线上读回分别报告。
